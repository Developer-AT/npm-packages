# Appinventiv NPM Packages

Internal monorepo of reusable **TypeScript** libraries for Node.js services. Each folder is an independent npm package under the **`@appinventiv`** scope, built with `tsc` and published separately.

## Packages

| Package | Folder | Description |
|---------|--------|-------------|
| [`@appinventiv/logger`](logger/) | `logger/` | Winston logger with trace / user / request context and plain `pInfo` / `pWarn` / `pError` helpers |
| [`@appinventiv/rabbit-mq`](rabbit-mq/) | `rabbit-mq/` | RabbitMQ producer & consumer wrappers with singleton connection manager |
| [`@appinventiv/bull-mq`](bull-mq/) | `bull-mq/` | BullMQ queue, worker, and job scheduler wrappers with built-in Redis connection |
| [`@appinventiv/redis`](redis/) | `redis/` | ioredis read/write client helpers for caching, locks, and key operations |
| [`@appinventiv/aws-s3`](aws-s3/) | `aws-s3/` | AWS S3 upload, read, delete, and presigned URL utilities |
| [`@appinventiv/aws-secret-manager`](aws-secret-manager/) | `aws-secret-manager/` | AWS Secrets Manager secret retrieval |
| [`@appinventiv/smtp-mail`](smtp-mail/) | `smtp-mail/` | SMTP email sending via Nodemailer with flexible transport config |

Package-specific installation, API, and examples live in each folder’s **README.md**.

Each package follows the same layout:

```
<package>/
├── src/           # TypeScript source
├── dist/          # compiled output (generated by npm run build)
├── package.json
├── tsconfig.json
└── README.md
```

## Requirements

- **Node.js** 18+ (recommended)
- **npm** 9+

## Development

### Install dependencies

From a package directory:

```bash
cd logger   # or any package folder
npm install
```

### Build

```bash
npm run build
```

This runs `tsc` and emits JavaScript + `.d.ts` files into `dist/`.

### Build all packages

From the repo root:

```bash
for dir in logger rabbit-mq bull-mq redis aws-s3 aws-secret-manager smtp-mail; do
  echo "Building $dir..."
  (cd "$dir" && npm install && npm run build)
done
```

## Using a package in another project

```bash
npm install @appinventiv/logger
# or
npm install @appinventiv/rabbit-mq
```

Then import from the published entry point (`dist/index.js` / types from `dist/index.d.ts`). See the package README for setup (e.g. `rabbitMQ.setConfig`, `bullMQ.initFromRedisConfig`, `redis.initiateRedisConnection`).

## Publishing

1. Bump `version` in the package’s `package.json`.
2. Build: `npm run build`.
3. Publish (with registry access): `npm publish --access public` from that package folder.

Only publish from packages you intend to release; each `package.json` is independent.

## Design conventions

Shared patterns across packages:

- **Singleton exports** — e.g. `logger`, `rabbitMQ`, `bullMQ`, `redis`, `producer`, `consumer`, `job`, `worker`
- **Configure once at startup** — connection/config on a manager or `init*` method before use
- **TypeScript-first** — strict-ish `tsconfig`, declarations emitted to `dist/`
- **Thin wrappers** — opinionated defaults around mature libraries (Winston, amqplib, BullMQ, ioredis, AWS SDK, Nodemailer)

## Git ignore

All `node_modules` folders are ignored via the root [`.gitignore`](.gitignore) rule `**/node_modules/`. Do not add per-package `.gitignore` files for dependencies unless you need package-specific exceptions.
